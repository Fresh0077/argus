# 修复建议与差异预览

> 阶段 16 产物。核心原则：**只生成候选补丁，不自动修改用户代码。**

## 1. 定位与边界

ARGUS 的修复建议是**辅助材料**，不是已验证的修复：

- 模型可能误判漏洞，也可能给出错误、残缺或引入新问题的补丁；
- 服务端不会编译、执行或测试修复后的代码；
- 界面不会自动应用补丁，也不会覆盖上传内容或原文件；
- 用户必须主动点击「复制修复代码」或「下载为新文件」，且仍需自行审查与测试。

因此界面与文档统一使用「候选补丁」「修复建议」，不使用「已修复」「已验证」这类表述。

## 2. 数据流

```text
前端选中 Finding
  └─ POST /api/v1/repair { source_code, language, filename, finding }
       ├─ 可用性检查：LLM_ENABLED / BASE_URL / API_KEY / MODEL
       ├─ 行号核对：发现行必须落在当前源码范围内
       ├─ 上下文裁剪：目标行前后各 10 行，总长度 ≤ LLM_MAX_INPUT_CHARS
       ├─ 调用模型（OpenAI-compatible /chat/completions）
       ├─ 结构化校验：JSON、字段、长度、空代码、未修改、行号前缀
       └─ 计算 unified diff → RepairSuggestion
  └─ 前端弹窗展示 diff、思路、解释、兼容性影响与未确认前提
       └─ 用户主动复制 / 下载，不修改原文件
```

## 3. 实际发送给模型的内容

只有以下内容会离开本机：

| 内容 | 说明 |
|---|---|
| 目标行前后各 10 行代码 | 带真实行号；超过 `LLM_MAX_INPUT_CHARS` 时从远离目标的一侧收缩。文件很短时整个文件可能都落在窗口内 |
| 发现的元数据 | 标题、漏洞类型、严重等级、行号、规则 ID、CWE、证据、说明与原有建议（长文本截断到 800 字符） |
| 语言与文件名 | 文件名仅用于上下文提示 |

**不会发送**：API key、扫描历史、其他用户的代码、服务器路径。
服务端不会主动发送整个大文件；但如果文件本身很短（不超过目标行前后各 10 行），
整个文件会自然落在上下文窗口内。需要完全避免出网时，请设置 `LLM_ENABLED=false`。
如果目标行本身超过长度上限，接口直接返回 `422`，不会截断半行代码。

## 4. 输出校验

模型输出先经过 `RepairModelOutput`（`extra="forbid"`）校验，再检查：

- `fixed_code` 去除可能的 Markdown 围栏后不能为空；
- 不能与原始目标行完全相同（"没有修改"不是修复）；
- 不能所有行都带 `12: ` 这类行号前缀（不能直接作为补丁使用）；
- 各字段长度不得超过上限。

不满足时返回 `502 llm_output_invalid`，**不会把不合格内容展示成修复建议**。

服务端还会用 `difflib` 重新计算 `original_code` 与 `diff`，不采信模型返回的"原始代码"。

## 5. 界面交互

- 在发现详情中点击「生成修复建议」，弹窗显示：
  - 风险声明（未经测试、必须人工审查）；
  - 修复思路、差异预览、解释、兼容性影响、未能确认的前提；
  - 关联发现与本次发送给模型的上下文行范围。
- 「复制修复代码」「下载为新文件」都必须由用户主动点击；
- 下载文件名形如 `views.fixed.py`，不会写入原文件；
- 历史详情不保存源代码，因此修复按钮置灰并说明原因；
- 上传文件只有在后端按 UTF-8 解码时才允许生成修复建议；GBK 等编码无法在浏览器中可靠还原文本，避免发送错位代码。

## 6. 不持久化

修复建议不写入 SQLite、不写入扫描历史、不写入日志。需要保留时请自行复制或下载。

## 7. 已知限制

- **无法可靠判断"无关修改"**：服务端只能检查"是否修改"与明显格式问题，
  不能证明补丁只改了目标行，也不能保证语义正确；
- 模型返回的代码若需要改动目标行之外的代码，diff 会如实显示，但应用时需要人工处理；
- 修复建议依赖发现的行号；没有行号的发现无法进入修复流程；
- 模型输出可能被截断（`LLM_MAX_OUTPUT_TOKENS`），截断后通常表现为 JSON 不合法并被拒绝；
- 不提供"应用补丁"按钮，这是刻意的安全设计。

## 8. 配置

复用 LLM 配置，无新增环境变量：

| 变量 | 作用 |
|---|---|
| `LLM_ENABLED` | 总开关；`false` 时修复接口返回 `503` |
| `LLM_BASE_URL` | OpenAI-compatible 服务地址 |
| `LLM_API_KEY` | 仅后端读取，绝不进入前端或响应 |
| `LLM_MODEL` | 模型名 |
| `LLM_TIMEOUT_SECONDS` | 单次请求超时 |
| `LLM_MAX_OUTPUT_TOKENS` | 输出长度上限 |
| `LLM_MAX_INPUT_CHARS` | 修复上下文的代码字符上限 |

## 9. 测试

全部使用假客户端，不依赖真实 API key，也不会发起网络请求：

```bash
cd backend
python -m pytest tests/test_repair.py -q
```

覆盖：上下文窗口与裁剪、目标行过长、无行号/越界、坏 JSON、缺字段、空代码、未修改、
带行号、围栏剥离、LLM 关闭、缺配置、超时/限流、HTTP 错误码与文案安全。
