# 分析设计

> 当前版本只保留 **特征提取 + LLM 语义分析**。
> 本地规则、启发式线索与 Semgrep 已从代码与主流程中移除；
> 旧历史记录中的相关来源仅为读取兼容保留，不再产生新结果。

## 1. 总体流程

```text
粘贴代码 / 上传文件
        ↓
输入校验（大小、扩展名、编码、控制字符）
        ↓
特征提取（语言、统计、结构；只作上下文）
        ↓
LLM 语义分析（可选开关 + 服务端总开关）
        ↓
结构化发现（严重等级、证据、行号、建议、置信度）
        ↓
扫描历史 → 报告导出
        ↓
可选的 LLM 修复建议
```

HTTP 请求包审计是独立入口：

```text
原始报文 → 解析 → 脱敏 → 可编辑预览 → 用户确认 → LLM → 发现
```

两条入口都不执行、不编译、不导入用户提交的代码；请求包审计也不重放请求。

## 2. 特征提取

实现：`backend/app/analyzers/extractor.py`、`stats.py`、`language.py`。

输出：

| 字段 | 内容 |
|---|---|
| `language` | 识别出的语言或 `null` |
| `language_source` | `explicit` / `extension` / `heuristic` / `none` |
| `language_evidence` | 判断依据，例如“扩展名 .py” |
| `stats` | 总行数、非空行、字符数、最长行 |
| `structure` | 函数/类大致数量、导入模块列表 |
| `notes` | 近似值与局限说明 |

特征提取**不判定安全性**，只把代码规模和依赖信息作为 LLM 的上下文。
函数数、类数按语言声明模式近似统计，不做语法树解析。

## 3. LLM 分析

实现：`backend/app/analyzers/llm/`。

### 3.1 提示词

- 代码放在带随机后缀的 `<code-…>` 标签中，明确声明为不可信数据；
- 每行前写真实行号，模型不需要自己数；
- 特征摘要以紧凑文本加入用户消息；
- 超长代码按整行截断，并写明实际发送范围；
- 系统提示词要求忽略代码/注释/字符串中的提示注入。

### 3.2 输出校验

模型输出先经 `LlmFinding`（`extra="forbid"`）严格校验，再转换成 `Finding`：

- 行号必须落在源码范围内，越界丢弃，不钳制；
- 证据按行号从源码截取，不直接采用模型给的片段；
- 类别必须是受控词表；
- 非法 JSON、空内容、全部条目不合格分别报失败；
- `confidence` 是模型自评，不是漏洞概率。

### 3.3 失败与状态

- 服务端 `LLM_ENABLED=false` → `skipped`；
- 缺少地址/密钥/模型名 → `unavailable`；
- 超时、429、5xx、网络错误、输出不合格 → `failed`；
- 任何失败都不会被表述成“未发现漏洞”；
- `findings` 为空只在 LLM 成功执行时才可能表示“本次未报告问题”。

## 4. 扫描响应

`ScanResponse` 包含：

- `scan_id`、`status`、`detected_language`、`source_encoding`；
- `findings`、`summary`、`duration_ms`；
- `analyzer_status`：语言识别、特征提取、LLM；
- `features`：完整的特征提取结果；
- `disclaimer`。

`status=completed` 要求所有分析器成功；LLM 未启用或失败时为 `partial`。

## 5. 修复建议

`POST /api/v1/repair` 使用 LLM 生成候选补丁：

- 只发送目标行前后各 10 行、且不超过 `LLM_MAX_INPUT_CHARS` 的上下文；
- 严格校验模型 JSON、字段、代码是否真的变化；
- 返回统一 diff，只供复制/下载；
- 不修改文件、不执行代码、不写历史。

## 6. 请求包审计

独立于源码扫描：

- 解析 HTTP/1.x 文本报文，保留真实行号；
- 自动脱敏 Authorization、Cookie、敏感参数与已知令牌；
- 预览可编辑，编辑后前端重新计算 SHA-256；
- 用户确认后，服务端以提交的 `redacted_request` 为准调用 LLM；
- 不重放请求、不访问目标、不写历史或报告。

详见 [`request-audit.md`](request-audit.md)。

## 7. 已知局限

- LLM 不可复现，可能误报和漏报；没有 key 时不会产生发现。
- 特征提取只提供上下文，不能单独判定漏洞。
- 单文件分析，不做跨文件/跨函数完整数据流追踪。
- 修复建议未经编译、执行或测试，必须人工复核。
- 请求包审计只看到报文，不能确认服务端漏洞。
- 旧历史记录可能包含 `static_rule` / `heuristic` / `semgrep` 来源，
  只是为了能继续读取；新扫描不会再生成这些来源。
